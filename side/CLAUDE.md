# 무협 가로판 — 작업 지침

세로 화면에서 **가로로 나아가는** 방치형. 주인공은 오른쪽으로 달리고, 적은 오른쪽에서 오고, 싸움은 멈추지 않는다.
옛 판(저장소 루트 `src/`)이 너무 무거워져 여기서 작게 다시 시작했다. **옛 판은 건드리지 않는다** — 그림(`../assets/`)과 수치만 빌려 온다.

한국어로 대화하고 주석도 한국어로 쓴다.

## 지킬 것

1. **코어 화면이 보기 좋아질 때까지 다른 걸 안 넣는다.** 시스템은 하나씩, 사용자가 고른 순서로 되살린다. 옛 판은 15개를 쌓았다가 첫 30분에 쓸 수 있는 게 둘뿐이었다.
2. **숫자는 `src/00-data.js` 에만.**
3. **밸런스 곡선(`DIFF`·`GROW`·`REALM`·`SILVER`·`TRAIN`)은 옛 판 확정값이다.** 체감 속도를 고치려고 건드리지 않는다 — 박자는 `WAVE`·`HERO.spd` 로 맞추고 `node test.js` 출력으로 판단한다.
4. **그림은 새로 그리지 않는다.** 옛 `assets/` 를 쓰고, 없으면 제미나이 프롬프트를 사용자에게 적어 준다. 새 키는 `assetKeys()` 에 들어가야 빌드에 실린다(없는 키는 빌드가 실패한다).
5. **바꾸면 크로뮴으로 찍어 사용자에게 보인다.** jsdom 은 그림을 못 본다.
6. **패널을 통째로 다시 만들지 않는다**(`innerHTML` 재생성 금지) — 글자 노드만 바꾼다. 옛 판에서 탭이 먹히던 원인이다.
7. `createRadialGradient` 금지(jsdom 스텁 없음). `createLinearGradient` 는 try 로 감싼다.

## 명령

```bash
node build.js     # src/ + 필요한 그림만 → dist/side.html (한 파일, 약 1.9MB)
node test.js      # jsdom 구동 검사 + 진행 박자 (SIM_MIN=분, 기본 30) — 20초 안쪽
```

`npm i` 는 저장소 루트에서(jsdom·playwright-core). 크로뮴은 `/opt/pw-browsers/chromium-1243/chrome-linux64/chrome`.
게시는 `dist/side.html` 한 장을 아티팩트로.

## 구조

```
src/00-data.js    설계 숫자 전부 + assetKeys()
src/10-engine.js  캔버스·크기(resize)·그림 로딩·헬퍼
src/20-game.js    상태 S·P, 수식, step(dt), 저장
src/30-render.js  장면 그리기 (캔버스)
src/40-ui.js      글자·패널 (HTML)
src/50-main.js    시작·루프
shell.html        껍데기 + CSS. build.js 가 코드를 끼워 넣는다
```

## 화면

- 위 56% = **장면**(캔버스, 논리 폭 440) · 아래 = **패널**(HTML). 글자·간격은 `#app` 의 `--w` 에 비례(em)라 기기 폭이 달라도 비율이 같다.
- 장면 순서: 하늘 → 원경(천천히 흐름) → 밤 안개(원경만 덮는다) → 중경 대나무 실루엣 → 땅·자갈 → 인물 → 연출 → 위쪽 어둠.
  **원경만 어둡게 덮고 인물은 그 위에 밝게** — 어두운 톤에서도 싸움이 읽히는 이유다.
- 톤 레퍼런스: Soda Legend — 어두운 남색 안개, 캡슐 HUD, 가는 선, 강조색 하나(강철 파랑), 보스만 장밋빛.
- 적 그림은 전부 오른쪽 보기라 **항상 뒤집어** 그린다(적은 늘 왼쪽을 본다).

## 싸움의 박자

세계는 x 한 줄. **한 떼를 잡고 → 달려서 → 다음 떼를 만난다.** 남은 적이 `WAVE.left` 이하면 다음 떼를 화면 밖 오른쪽에 미리 세운다.
주인공은 닿는 적을 한 번에 다 친다(가로 한 줄이라 범위 판정이 곧 사거리). 쓰러지면 3초 운기조식 뒤 제자리에서 다시 — 잃는 건 시간뿐.
10단계를 채우면 수호자. 지면 10단계로 물러나고, 이기면 지금은 10단계에서 계속 사냥한다(다음 구역 없음).
