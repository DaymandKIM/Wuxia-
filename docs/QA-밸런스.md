# QA·밸런스 점검표

밸런스 판단은 감이 아니라 `node sim.js` 출력으로 한다 (CLAUDE.md 규칙 4).
**새 성장 축이 들어오면 이 표와 `sim.js`의 spend()에 반드시 추가한다** —
여기 빠진 축은 시뮬에 안 잡혀서 그 계수를 바꿔도 밸런스 검증이 안 된다.

## 시뮬에 반영되는 성장 축 (v2.1 기준)

| 축 | 숫자 위치 (00-data.js) | 시뮬 반영 방식 |
|---|---|---|
| 수련 8스텟 (스텟별 cb·cg 곡선) | `TRAIN` | spend()가 싼 것부터 구매 |
| 무공 습득 — 초식 자동 시전·심법 % | `ARTS` | spend()의 learnArt + 전투 코드가 실제 시전 |
| 숙련 성 돌파 — 연마 상한+게이지 만충 필요 | `MASTERY` | spend()의 breakArt, artEff가 전투에 적용 |
| 무공 연마 — 레벨당 +1.5%, 상한 성×10 | `MASTERY` (lv*) | spend()의 levelArt (틱당 최대 5회) |
| 경지 배수 성장 (×1.31/승급) | `REALM` `GROW` | 처치 수련치로 자동 |
| 은자 수입 (+은자 획득 스텟) | `SILVER` | killSilver |
| 적 강도 지수 곡선 | `DIFF` `BOSS` | foeHp/foeDmg |
| **문파 무공도 (스킬트리)** — 경지 포인트로 노드 개방, 패시브 %·무공 마디 | `TREE`(65b-treedata)·`SKILLTREE` | spend()가 열린 노드를 무공 마디 우선·싼 것부터 익힘. treeBonus가 heroDmg 등 전투 수식에 합산(수련과 별개 축), 무공 마디는 S.arts로 자동 시전 |
| **성장형 기본공격** — 성급대로 동작 해금 | `ATKMOVES` | 전투 시각·판정 동일(스프라이트만 교대), DPS 영향 없음 |
| **장비** (v2.66) — 3자리 % 보너스, 처치 드랍 자동 장착(전승)·판매, 은자 강화 | `EQUIP` | 드랍·장착·판매는 전투 코드(rollDrop)가 그대로, spend()가 싼 자리부터 강화(틱당 3회). eqBonus가 heroDmg·hp·regen·crit·killSilver에 합산 |

## 시뮬 밖 — 별도로 검증하는 것

- **기연** (64-fate) — sim ORDER에 없다. 기능은 fatetest.js, 보상 크기는 수동 계산.
- **오프라인 정산** (65-save) — savetest.js + VERSION.md v1.9의 근사 모델 보정.
- 미구현: 발동 3모드 · 문파 — **들어오는 즉시 위 표와 spend()에 추가.**

## 실행과 판정

```bash
SIM_MIN=240 timeout 500 node sim.js    # 기준선은 VERSION.md 최신 밸런스 항목과 비교
```

- **은자 잔고**: 바닥 근처를 오가야 정상. 쌓이기만 하면 소비처 부족, 0에 붙어 있으면 곡선이 가파른 것.
- **진행 속도**: v2.0 곡선 유지 — 5분 죽림6 · 30분 폐촌 끝 · 1h 동굴 · 2h 설산 · 8h 천산 중반.
- **쓰러짐**: 0이면 너무 쉽고, 폭증하면 벽. 기준치는 VERSION.md 항목 참조.
- **스텟 곡선(cb·cg)을 바꾸면**: 스텟별 레벨 분포까지 본다 — 싼 것만 사고 비싼 스텟이 방치되면 재조정.
- **무공 계수(dmg·mul·heal·effPer)를 바꾸면**: 초식은 DPS에 직접 들어가므로 시뮬 재실행 필수.
- 밸런스 시뮬·분석은 에이전트에 맡겨 병렬로 돌려도 된다 — 단 결과 표와 판정은 VERSION.md에 남긴다.
